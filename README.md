# event-truth-analysis

一个把「信息判断」工程化的 Claude Code / WorkBuddy 技能：**把「这事是真的吗」变成一条可追溯、可反驳、可更新的证据链**。

不依赖任何具体事件、行业或领域——它处理的是**证据结构**，不是某件事。换个问题，拆命题的规则不变，打分标尺不变。

## 它解决什么

| 结构性失效 | 技能里的对策 |
|---|---|
| 来源不可追溯（截图、转述层层传递） | 证据池强制「出处 + 日期 + 链接」，查不到出处的只进待核实线索 |
| 数量冒充独立（十个账号转同一个帖） | 维度②「独立源交叉」＋账号矩阵排查清单 |
| 权威被当前提（权威有立场也有纠错问题） | 权威降权四问：原始数据、独立验证、可证伪、纠错机制 |
| 结论无法更新（判完就结束） | 存疑台账＋升级/降级条件＋定时复查，反转主动提醒 |

## 核心设计

**1. 命题主线** —— 分析对象不是「事件」，是「命题」

一个事件 = 若干可独立判定的命题：

- 命题 A：**发生了什么**（可核验的事件陈述）
- 命题 B：**为什么**（原因与责任归因）
- 命题 C：**会怎样**（现实影响与风险）

混在一起判断，会把「事情发生过」的确定性，误借给「原因是设计问题」这种推测。分开后每个命题有独立的证据要求、独立的置信度、独立的待验证条件。

**2. 双轨证据池** —— 事实证据与分析观点绝不混用

- **E 轨（事实证据）**：可真可假、可核验；必带出处+日期+链接；喂事实层，参与维度①-⑤打分
- **A 轨（分析观点）**：无法核验真假，只能评估逻辑好坏；喂分析层，**只允许**参与维度⑥（可反推性）

> 防火墙：「分析得头头是道」≠「有证据」。同一段素材可以被解读出十种「内幕」，它们全部属于 A 轨——撑不起任何一个命题的置信度。

**3. 三层框架** —— 多元输入，收敛输出

- **事实层**：证据收敛；记录遮蔽信号（不记录/不披露/选择性披露/口径变化/污染反制），把「缺失」本身记为事实
- **分析层**：多元解释，用「动机合理·因果清晰·不矛盾·能反推」筛选；标出最自洽解释、被降级解释、未排除的替代原因
- **隐蔽层**：合理推测必须可检验、有证据约束、能反推，三者缺一降级为叙事

**4. 六维度计分置信度** —— 让每个分数都能被复核

| 维度 | +1 | 0 | −1 |
|---|---|---|---|
| ① 原始证据质量 | 有一手证据 | 仅二手互洽 | 仅三手/无原始出处 |
| ② 独立源交叉 | ≥3 个真正独立源 | 2 个或独立性存疑 | 单一源/账号矩阵同源 |
| ③ 利益方行为一致性 | 行为与命题方向一致 | 中性/矛盾 | 行为与命题相反 |
| ④ 反证与替代解释 | 无实质反证 | 存在但弱 | 有强反证或未排除 |
| ⑤ 遮蔽信号 | 无遮蔽，数据公开 | 局部遮蔽 | 关键数据被遮蔽 |
| ⑥ 可反推性 | 主解释反推通过 | 部分通过 | 反推不通 |

总分映射（预设标尺，禁止拍脑袋给数字）：

| 总分 | 档位 | 置信度区间 |
|---|---|---|
| ≥ +4 | 已证实 | 85–95% |
| +1 ~ +3 | 部分证实/争议中 | 55–80% |
| −1 ~ 0 | 待核实 | 35–50% |
| ≤ −2 | 可疑/倾向否定 | <35% |

核心数据被遮蔽时，无论总分多少，置信度封顶并标注「受遮蔽暂不可判定」。

**5. 存疑台账** —— 结论不是终点，是待验证状态

凡档位不是「已证实」的命题自动挂账：命题、来源、证据等级、当前可信度、**升级/降级条件**、**复查时间**。条件必须锚定分析中留下的具体缺口（被遮蔽的数据、未排除的替代解释），不许凭空设。

## 安装

### WorkBuddy（用户级，全部会话可用）

```bash
git clone https://github.com/jassbin/event-truth-analysis.git \
  ~/.workbuddy/skills/event-truth-analysis
```

Windows（PowerShell）：

```powershell
git clone https://github.com/jassbin/event-truth-analysis.git "$env:USERPROFILE\.workbuddy\skills\event-truth-analysis"
```

安装后重开一个会话即可。技能按 `SKILL.md` 的 description 自动匹配触发，无需手动调用。

### Claude Code / 兼容 Agent Skills 的客户端

```bash
git clone https://github.com/jassbin/event-truth-analysis.git \
  ~/.claude/skills/event-truth-analysis
```

### 项目级安装（只对某个项目生效）

```bash
git clone https://github.com/jassbin/event-truth-analysis.git \
  <你的项目>/.workbuddy/skills/event-truth-analysis
```

## 使用

直接问就行，技能会按描述自动触发：

- 「XX 事件是真的吗？有这么不结实吗？」
- 「这个爆料靠谱吗，帮我交叉验证一下」
- 「这篇内幕文章有多少是真的」
- 「官方通报和网上说法不一致，信谁」

也可以显式点名，要求走完整流程：

> 用 event-truth-analysis 完整流程分析：<事件描述>

## 输出

强制报告骨架，**先结论后论证**：

```
0. 执行摘要 —— 各命题一句话 + 档位 + 总分（≤5 行）
1. 定位表（事件类型 / 信息状态 / 归谁管）
2. 命题清单
3. 证据池（编号表，双轨）
4. 逐命题分析（证据引用 → 三层筛选 → 维度计分表 + 推理链）
5. 存疑台账
6. 方法与局限（跳过了什么、遮蔽缺口、标尺修正说明）
7. 综合结论（回应用户最初那句话，不引入新证据）
```

任何一个置信度数字都能倒查：**置信度 → 维度 → 证据编号 → 原始链接**。

## 设计原则

- **来源属性不判真假**：官方和民间都可能真、都可能假。来源的激励结构和纠错机制只影响先验可信度，最终看证据和反推。
- **接受概率性真实**：很多事件无法一次定论。可信表述是「目前多源证据支持……，但……仍待核实」。
- **判断、传播、行动分开**：判断可以存疑记录；传播默认只限多源证实且必要的信息；行动按「可信度 × 影响」四象限。
- **不做无限悬置**：找不到破绽 ≠ 已证实。用结构化存疑（台账 + 复查时间），不各信一半，也不永久挂着。
